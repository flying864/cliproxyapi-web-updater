# 部署与安全边界

返回 [README](../README.md)。本页面向负责主机的管理员；不熟悉 Linux 权限时，不要直接修改线上目录。

## 主机目录与身份

- `/opt/cliproxyapi` 及主二进制保持 root 控制、不可被组或其他用户写入，例如应用目录为 `root:cliproxy 750`。
- `config.yaml` 必须是安全普通文件，可由 `cliproxy` 读写，以便管理 API 保存配置。例如 `cliproxy:cliproxy 600` 或 `root:cliproxy 660`；不能允许其他用户读写，不能使用不安全链接。
- 插件目录可为 `cliproxy:cliproxy 700`，也可保留已有安全 root-owned 布局；不能组/其他可写。安装器不递归 chmod/chown，也不强制改变已有权限。root-owned 布局仍需保证主服务可以读取插件；商店安装另需写权限。
- `/usr/local/libexec` 中的 Worker 和辅助代码由 root 控制。服务可写插件目录内的文件操作以服务账户执行，不以 root 加载其中的动态库。
- `/root/cliproxyapi-admin-key` 只用于固定本机管理 API，不写入 UI 或日志。插件自身不写入浏览器持久存储。按用户“记住密码”选择，可在同源管理中心内只读复用对应当前服务的登录记录；登出撤销自动来源，手动输入优先。独立打开或格式不匹配时需手动输入。仅在可信管理入口使用。

安装器只接受固定主机布局和可明确解析的服务参数，不改主 service、反向代理或业务模型设置。它会通过管理 API 启用本插件并保留其他插件配置；若全局关闭插件但其他插件被标记启用，会拒绝默认激活，留给管理员决定。

## 一次更新的流程

1. 校验身份、路径、运行版本和用户确认的正式版本；确认后官方最新版本又变化时，要求重新检查和确认。不自动降级。
2. 从固定官方 CLIProxyAPI 仓库下载程序包和校验文件，检查 SHA256、归档结构及 ELF 架构；不接受用户传入的下载地址。
3. 备份旧二进制、配置、已批准的实际 OAuth 目录和插件数据。读取运行数据时降权；拒绝链接、特殊文件、超限或读取中变化的数据。
4. 在 root 私有目录持久保存恢复事务，然后停主服务、原子替换二进制、启动原服务。
5. 核对实际运行版本、本机 API 就绪及短暂稳定窗口；失败尝试恢复旧二进制。恢复不重新联网下载。

OAuth 路径在初始化时通过 API 确认，存于 `/var/lib/cliproxy-updater/deployment.json`。升级前再次查询比对，变化即中止；可写配置不能指挥 root 备份任意目录。

## 不能保证什么

- **自动恢复只恢复二进制**，不覆盖 config/OAuth。新程序的数据迁移可能不可逆；运行数据备份也不是数据库式一致性快照。
- 同源 SHA256 可以发现传输损坏，不能独立证明发布者身份，也不能抵御发布账号被攻陷。
- 原生插件和主服务同进程；安装及升级可能短暂中断 API。默认健康检查不执行可能收费的模型调用或图片生成。
- 安装器对普通异常/信号提供有限恢复；SIGKILL 或断电遗留的安装快照需人工审查。不能把安装事务等同于 Worker 的持久恢复事务。
- JSON 解析进行有界结构、分隔符、数字、重复字段和顶层字段校验，并非通用 Unicode JSON 验证器；官方宿主及可信 Worker 的正常序列化仍属信任边界。

测试范围和未验证事项见 [AUDIT](../AUDIT.md)，故障处理见[运维与恢复](OPERATIONS.md)。
